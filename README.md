# Что делает скрипт mini-RMMv3.ps1

Это графическая утилита на PowerShell (Windows Forms) для удалённого администрирования компьютеров в сети или домене с одного рабочего места. Оператор вводит имя целевого ПК и выбирает нужное действие из выпадающего списка — программа выполняет его по сети (через WinRM/PowerShell Remoting, WMI или локальные утилиты) и показывает результат в окне лога.

## Интерфейс

Главное окно «Мини-RMM» содержит пять текстовых полей и несколько кнопок.

Поле «Имя компьютера» — имя или адрес целевого ПК. Используется почти всеми действиями.

Поле «Пользователь» — домен и логин (формат `ДОМЕН\Логин`). Нужно только для действий 15 (блокировка через планировщик) и 18 (tsdiscon).

Поле «MAC (для WOL)» — MAC-адрес для включения машины по сети.

Поле «Сообщение» — многострочный текст для отправки пользователю.

Выпадающий список «Действие» — 24 встроенные операции.

Кнопка «Выполнить» (также работает по Enter) запускает выбранное действие.

Кнопка «Кто залогинен?» — быстрый вызов процедуры показа активных сессий.

Кнопка «RDP» — запускает `mstsc.exe /v:<ПК>` для подключения к рабочему столу.

Кнопка «Очистить лог» — стирает содержимое окна вывода.

Кнопка «Сохранить лог» — открывает диалог сохранения и пишет журнал в `.txt` в кодировке UTF-8.

Окно вывода (моноширинный шрифт Consolas) — накапливает журнал, автоматически прокручивается вниз, доступно только для чтения.

## Вспомогательные функции

`Write-UIOutput` — печатает строку в окно лога, прокручивает вниз и вызывает `DoEvents()`, чтобы интерфейс не подвисал на долгих операциях.

`Show-LoggedInUsers` — показывает всех залогиненных пользователей на удалённом ПК двумя способами. Во-первых, через утилиту `quser` (с правильной кодировкой 866, чтобы кириллица читалась корректно) — выводятся все сессии. Во-вторых, через CIM (`Win32_LogonSession` + `Win32_LoggedOnUser`) — детализированно: домен, имя пользователя, тип входа (интерактивный, RDP или кэшированный) и время входа. Системные учётные записи (DWM-, UMFD-, NT AUTHORITY, SYSTEM) отфильтровываются.

## Логика кнопки «Выполнить»

Сначала скрипт читает все поля и индекс действия. Если выбрано хоть какое-то действие, печатает «шапку» с датой, временем, названием действия и именем ПК. Затем проверяет: для всех действий, кроме 3 (WOL), требуется имя ПК, и делается предварительный ping (`Test-Connection -Count 1`). Если хост не отвечает — выводится сообщение «недоступен, отмена», и действие не выполняется. Для WOL проверка не нужна, потому что пакет отправляется на broadcast-адрес.

## Действия 1–24

Действие 1 — удалённая перезагрузка через `Restart-Computer -Force -AsJob`.

Действие 2 — получение MAC-адресов активных сетевых адаптеров через WMI (`Win32_NetworkAdapterConfiguration` с фильтром `IPEnabled=True`). Показывает описание адаптера и MAC.

Действие 3 — Wake-on-LAN. Собирается magic-пакет (6 байт 0xFF + MAC-адрес, повторённый 16 раз) и отправляется по UDP на `255.255.255.255:9`. Имя ПК и ping не нужны — достаточно MAC.

Действие 4 — разлогин всех RDP-сессий на удалённом ПК. Через `quser` находятся строки с `rdp-tcp`, из них извлекается ID сессии, и для каждой выполняется `logoff <ID>`.

Действие 5 — аптайм и время последней перезагрузки через `Win32_OperatingSystem.LastBootUpTime`. Показывается дата загрузки и продолжительность работы в днях, часах, минутах.

Действие 6 — то же, что и кнопка «Кто залогинен?» — вызов `Show-LoggedInUsers`.

Действие 7 — информация о системе: имя ПК, домен или рабочая группа, производитель, модель, серийный номер, версия ОС (build и разрядность), объём RAM, модель CPU и число ядер/потоков, размер и свободное место на диске C:.

Действие 8 — сетевые параметры всех активных адаптеров: IP-адреса, маски, шлюзы, DNS-серверы.

Действие 9 — очистка очереди печати. Останавливается служба Spooler, удаляются файлы из `C:\Windows\System32\spool\PRINTERS`, служба запускается снова.

Действие 10 — отправка сообщения пользователю через `msg.exe *` (запуск через `Invoke-WmiMethod Win32_Process Create`). Текст берётся из поля «Сообщение».

Действие 11 — удаление профиля пользователя. Скрипт получает список папок в `C:\Users` (без системных), показывает отдельное диалоговое окно с выпадающим списком профилей, после подтверждения удаляет профиль через `Win32_UserProfile.Delete()` и дополнительно чистит папку через `Remove-Item -Recurse`. Если пользователь сейчас залогинен — выводится предупреждение, что удаление может не сработать.

Действие 12 — очистка ETL-логов и отчётов WER. Удаляются файлы из `C:\ProgramData\Microsoft\Diagnosis\ETLLogs`, `...\ETLLogs\AutoLogger`, `...\Windows\WER\ReportQueue` и `...\WER\ReportArchive`. Для каждого каталога показывается, сколько мегабайт освобождено.

Действие 13 — health-check станции: последние ошибки уровня Error в журналах System и Application за 24 часа (до 10 на журнал), плюс статус важных служб WinRM и TermService.

Действие 14 — список сетевых дисков. Собирается тремя способами: чтение ветки реестра `HKEY_USERS\<SID>\Network` для каждого пользователя (показывает пользователя, букву диска, удалённый путь и провайдера), `Get-SmbMapping` (текущие SMB-подключения), `net use` (как резервный вариант) и `Win32_MappedLogicalDisk` через CIM.

Действие 15 — блокировка ПК методом Scheduled Task. Создаётся задача `RemoteLockTask`, запускающая `rundll32 user32.dll,LockWorkStation` в интерактивной сессии указанного пользователя (обязательно должен быть заполнен поле «Пользователь»). Задача запускается, ждётся 4 секунды, читается `LastTaskResult` (0 = успех), задача удаляется.

Действие 16 — блокировка ПК через PsExec. Требует наличия `PsExec.exe` в PATH. Команда: `psexec \\ПК -accepteula -i 1 -s -d rundll32.exe user32.dll,LockWorkStation`. Это запуск в интерактивной сессии (`-i 1`) от SYSTEM (`-s`).

Действие 17 — блокировка через прямой `rundll32` в Session 0. Часто не срабатывает из-за изоляции сессий, о чём предупреждает вывод — при неудаче рекомендуется использовать метод 15 или 16.

Действие 18 — блокировка/отключение сессии через `tsdiscon`. Скрипт получает `quser` на удалённом ПК, ищет строку указанного в поле «Пользователь» логина, извлекает ID сессии и вызывает `tsdiscon <ID>`. Это именно отключение, а не logoff — сессия сохраняется.

Действие 19 — `gpupdate /force` с перехватом вывода в кодировке 866 и построчным выводом результата.

Действие 20 — завершение процесса. В диалоге InputBox спрашивается имя процесса (по умолчанию `excel.exe`), расширение `.exe` отрезается, и через `Stop-Process -Force` процесс убивается на удалённом ПК. Если процесс не найден — сообщается об этом.

Действие 21 — очистка временных файлов. Удаляются содержимое `C:\Windows\Temp` и все папки `C:\Users\*\AppData\Local\Temp` (рекурсивно). В конце показывается, сколько объектов удалено.

Действие 22 — перезапуск конкретной службы. В InputBox вводится имя службы (по умолчанию `LanmanServer`), на удалённом ПК выполняется `Restart-Service -Force`.

Действие 23 — список установленного ПО. Читаются ключи реестра `HKLM:\Software\Microsoft\Windows\CurrentVersion\Uninstall\*` и ветка Wow6432Node для 32-битных программ. В InputBox можно ввести подстроку для поиска (например, «Word» или «1C») — если оставить пустым, выводится весь список. Для каждой программы показывается название и версия.

Действие 24 — ping с удалённой машины. В InputBox вводится IP или имя хоста (по умолчанию `8.8.8.8`), на удалённом ПК выполняется `Test-Connection -Count 4`, результаты (адрес и время отклика) выводятся построчно.

## Общая схема работы

Все действия, работающие через WinRM (`Invoke-Command`), требуют включённой службы WinRM на целевых ПК и наличия прав локального администратора. Действия 1, 3 и локальные вызовы (`mstsc`, `PsExec`) работают напрямую с машины оператора. Для старых системных вызовов (`quser`, `gpupdate`, `net use`) скрипт вручную переключает кодировку консоли на 866 (OEM-кириллица), чтобы русский текст в журналах и результатах читался корректно. Окно лога очищается только по кнопке «Очистить лог»; каждый запуск действия добавляет новую «шапку» с датой и разделителями, поэтому в одном сеансе можно накопить историю по нескольким ПК и сохранить её в файл.
